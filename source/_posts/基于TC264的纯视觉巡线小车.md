## 项目架构

本工程基于逐飞科技 TC264 开源库，主控为英飞凌 AURIX TC264D（双核 TriCore），使用 MT9V03X 灰度摄像头（188×120）识别赛道，双编码器闭环控制左右电机，舵机负责方向。

> **为什么是双核？**
> 可以把 TC264 的双核想象成一辆车上的「司机」和「领航员」：CPU0 是司机，双手不能离开方向盘——所有实时控制（方向环、速度环、编码器采样）都跑在它的定时中断里；CPU1 是领航员，负责看路（图像处理）、记笔记（屏幕显示）、和后方基地通话（WiFi 上位机）。两人通过共享变量交换信息，谁也不阻塞谁。


### 硬件资源

- 左电机 PWM：P33.6，方向 P33.7；右电机 PWM：P02.4，方向 P02.5
- 舵机 PWM：P33.9，频率 333Hz
- 编码器：GPT12 的 TIM6（左）/ TIM5（右），标定 11485 count/m
- 摄像头：MT9V03X，VSYNC + DMA 采集
- 显示：IPS200 SPI；无线：逐飞 WiFi SPI 模块（TCP 客户端）

### 双核分工及其中断分配

**CPU0（司机）**：实时控制，所有中断都归它执行。
- 2ms（CCU61 CH0）→ 方向环 + 舵机滤波/限幅
- 5ms（CCU60 CH0）→ 系统计时、IMU
- 10ms（CCU61 CH1）→ 编码器采样、里程、速度环、出赛道保护
- 1s（CCU60 CH1）→ 帧率统计

**CPU1（领航员）**：视觉与通信，跑主循环调度（非中断）。
- 10ms 按键扫描；33ms WiFi 图像上传；100ms 刷屏/数据上传

> ***关键***：PIT、摄像头 DMA、串口中断全部用 `IFX_INTERRUPT(..., 0, ...)` 绑在 CPU0，方向环和速度环都在中断上下文里跑；CPU1 只负责图像处理和 WiFi，不碰实时控制。

## 常用算法


### 基础循迹及其图像处理

#### 计算误差流程

由大津法得到二值化图像，然后通过迷宫罚计算出左右边界，取一个前瞻点与图像中值之差作为误差

#### 大津法二值化

摄像头输出的是 188×120 的灰度图，要提取赛道边线，第一步就是把灰度图变成黑白二值图——赛道为白、背景为黑。本工程用的是**全局大津法（Otsu）**。

> **大津法是什么？**
> 可以把它想象成一个「自动找最佳切割点」的分割师：遍历所有可能的阈值（0~255），计算每个阈值下「赛道像素」和「背景像素」两组之间的类间方差，方差最大的那个阈值就是最佳分割点——它让两组分得最开。

**优点**：无需手动设阈值，能自动适应光照变化。

**局限**：当画面出现局部强光/阴影（比如赛道上有光斑、远处有反光）时，全局单一阈值会让局部区域过曝或丢失信息。本工程后续通过逆透视+点云处理来弥补。

##### 分块大津法与全局大津法

工程里实现了两套大津法，各有适用场景。

> 图像尺寸 188×120，分块参数：块宽 188（整行）、块高 20 → 纵向切成 6 条，每条独立算阈值。

**全局大津法（双重迭代版）** —— `image_threshold()`

先用全图直方图跑一次大津得到 T1，然后把 T1 以下的灰度直方合并到 T1 桶里再跑一次得到 T2。这么做的目的是压掉暗端噪声，让阈值更稳定。核心计算 `otsu_compute` 用了一个等价变换，避免除法：

```c
// 类间方差 = wB * wF * (μB - μF)²
// 用 sumB*N - sum*wB 避免除法
float diff = sum_back * pixel_count - sum_total * w_back;
float var = (diff * diff) / (w_back * w_fore);
```

完整流程：

```c
void image_threshold(const uint8 image[MT9V03X_H][MT9V03X_W])
{
    uint32 histogram[256] = {0};
    uint32 pixel_count = 0;

    // 隔行采样统计直方图
    for (y = 0; y < MT9V03X_H; y += 2)
        for (x = 0; x < MT9V03X_W; x += 2)
            histogram[image[y][x]]++, pixel_count++;

    uint8 threshold = otsu_compute(histogram, pixel_count);   // 第一次 T1

    // 把 T1 以下的直方合并到 T1 桶
    uint32 low_sum = 0;
    for (level = 0; level < threshold; level++)
        low_sum += histogram[level], histogram[level] = 0;
    histogram[threshold] += low_sum;

    threshold = otsu_compute(histogram, pixel_count);          // 第二次 T2
    for (y = 0; y < MT9V03X_H; y++)
        for (x = 0; x < MT9V03X_W; x++)
            image_binary[y][x] = (image[y][x] < threshold) ? 0 : 255;
}
```

**分块大津法** —— `image_threshold_block()`

把画面切成 6 个 188×20 的横条，每条用 `otsu_local_threshold` 独立计算阈值，存进 `image_threshold_map[6][1]`，再逐像素查表二值化。

```c
void image_threshold_block(const uint8 image[MT9V03X_H][MT9V03X_W])
{
    // 1. 每块独立算阈值，写入 image_threshold_map
    for (block_y = 0; block_y < IMAGE_OTSU_BLOCK_ROWS; block_y++) {
        y_top    = block_y * IMAGE_OTSU_BLOCK_H;
        y_bottle = y_top + IMAGE_OTSU_BLOCK_H;
        for (block_x = 0; block_x < IMAGE_OTSU_BLOCK_COLS; block_x++) {
            x_left  = block_x * IMAGE_OTSU_BLOCK_W;
            x_right = x_left + IMAGE_OTSU_BLOCK_W;
            image_threshold_map[block_y][block_x] =
                otsu_local_threshold(image, x_left, x_right, y_top, y_bottle);
        }
    }
    // 2. 逐像素查对应块的阈值二值化
    for (y = 0; y < MT9V03X_H; y++)
        for (x = 0; x < MT9V03X_W; x++) {
            block_x = x / IMAGE_OTSU_BLOCK_W;
            block_y = y / IMAGE_OTSU_BLOCK_H;
            image_binary[y][x] =
                (image[y][x] < image_threshold_map[block_y][block_x]) ? 0 : 255;
        }
}
```
#### 迷宫法

**两者对比**

| 方式 | 优点 | 局限 |
|------|------|------|
| 全局双重迭代 | 计算简单，全图阈值统一 | 光照不均时暗部/亮部会丢线 |
| 分块 | 能适应局部光照差异 | 块之间阈值跳变，可能产生横向锯齿 |

工程默认走全局大津法，配合逆透视 + 点云处理来修正局部过曝/阴影；分块版本保留作对比实验，阈值可通过 `display_otsu_thresholds` 打印到 IPS200 屏幕调试。

##### 巡线流水线：从二值图到方向误差

二值化之后，巡线的核心流程是：**找起始行 → 迷宫法逐行跟踪左右边界 → 取前瞻点中线与图像中心的偏差作为方向误差**。

**第一步：找起始行 `find_binary_start`**

从图像底部往上扫描，每行枚举所有连续白色区间，选出中心最靠近上一帧中心（首帧用图像中点）的那条，要求区间两侧都是黑色像素，这样才能同时拿到左右两个边界。找到第一行就停，作为迷宫法的起点。

```c
for (yy = PERS_H - 2; yy >= 2; yy--) {
    // 找完整白段：左/右边界外侧必须是黑像素
    if (run_left > 1 && run_right < PERS_W - 2 &&
        binary[yy][run_left - 1]  < THRESH &&
        binary[yy][run_right + 1] < THRESH) {
        score = abs(center - previous_center) * 3
              + abs(width - previous_width);   // 与上一帧越连续分越低
        if (score < best_score) 记最佳左右边界;
    }
    if (best_left >= 0) return 1;   // 找到第一行就返回
}
```

**第二步：迷宫法逐行跟踪 `track_lane_by_rows`**

从起始行向上（远端）逐行推进，每行同样枚举白段，但选择标准改成「与上一行中心跳变最小 + 宽度最接近」，保证一行一对边界、点序只向前，避免回头、闭环和左右串线。每行拿到的 `(best_left, best_right)` 分别存入 `left_line_points` / `right_line_points`。

```c
score = center_jump * 4 + abs(width - previous_width);
if (score < best_score) { best_left = run_left; best_right = run_right; }
// 连续丢 2 行就停止，不硬补
if (best_left < 0) { if (++miss_count >= 2) break; continue; }
```

**第三步：前瞻点与误差计算 `calculation_error`**

拿到左右两条边界点序列后，在距离车头 `aim_distance` 的前瞻行 `target_y` 上采样左右边界的 x 坐标，取中点 `mx = (l_x + r_x) / 2`，与图像中心 `cx` 做差得到横向偏差，再用 **Pure Pursuit** 公式换算成转向角：

```c
dx = mx - cx;                          // 前瞻点相对车头的横向偏差
dy = cy - my + 0.2f;                   // 纵向距离
dn = sqrtf(dx * dx + dy * dy);
pure_rad = -atanf(2.0f * 0.3f * dx / (dn * dn));   // Pure Pursuit 曲率
pure_angle = pure_rad * 57.2958f / SMOTOR_RATE;    // 转成舵机量纲
```

> **为什么用 Pure Pursuit 而不是直接用 `mx - cx`？**
> 直接取横向偏差在直道还行，到了弯道前瞻点会横向飘移，误差和实际需要的转向角不成正比。Pure Pursuit 用 `2L·dx / dn²` 换算成曲率，物理意义是「以当前车速沿这个曲率走能正好到达前瞻点」，过弯更线性。

工程里还加了几层保护：动态前瞻距离（中线变短立即收近、恢复时每帧只延伸 1px）、直道 1° 死区、0.35/0.65 低通、单帧变化限幅 4°，确保方向环输入平滑不抽搐。

##### 迷宫法左右巡线

除了按行跟踪，工程里还实现了经典的**左手 / 右手定则迷宫法**：把白色赛道边缘当成迷宫的墙，巡线者贴着墙走。两个方向共用一套方向查找表，`dir` 取值 0=上、1=右、2=下、3=左。

```c
// 正前方、左前方、右前方的坐标增量
static const int16 edge_dir_front[4][2]     = { {0,-1}, {1,0}, {0,1}, {-1,0} };
static const int16 edge_dir_frontleft[4][2] = { {-1,-1}, {1,-1}, {1,1}, {-1,1} };
static const int16 edge_dir_frontright[4][2] = { {1,-1}, {1,1}, {-1,1}, {-1,-1} };
```

**左手定则 `findline_lefthand_binary`**：每一步优先看左前方——左前方有白就左转斜着走，否则看正前方——前方有白就直走，都没有就原地右转。连续右转 4 次（360°）说明走进死路，停止。

```c
while (step < max_points - 1 && turn < 4) {
    fx  = x + edge_dir_front[dir][0];       // 正前方
    fy  = y + edge_dir_front[dir][1];
    flx = x + edge_dir_frontleft[dir][0];   // 左前方
    fly = y + edge_dir_frontleft[dir][1];

    if (binary[fy][fx] >= THRESH) {
        if (binary[fly][flx] >= THRESH) {
            dir = (dir + 3) % 4;            // 左转 90°
            x = flx; y = fly;               // 斜走左前方
        } else {
            x = fx; y = fy;                 // 直行
        }
        turn = 0;
        points[++step][0] = x; points[step][1] = y;
    } else {
        dir = (dir + 1) % 4;                // 前方不通，右转 90°
        turn++;
    }
}
```

**右手定则 `findline_righthand_binary`**：完全镜像——优先看右前方，不通就左转：

```c
if (binary[fy][fx] >= THRESH) {
    if (binary[fry][frx] >= THRESH) {
        dir = (dir + 1) % 4;                // 右转 90°
        x = frx; y = fry;
    } else { x = fx; y = fy; }              // 直行
} else {
    dir = (dir + 3) % 4;                    // 左转 90°
    turn++;
}
```

**左右串线保护 `truncate_crossed_edges`**：两条边线各自独立走迷宫，在远端某一侧可能绕到对侧轮廓上。从起始行向上逐行配对左右点，一旦发现 `rx - lx <= 3`（左右点几乎重合，说明两条线缠在一起），就把该行之后的两边全部截断，只保留前面可信的部分。

> 左手 / 右手迷宫法的优点是对**弯道、环岛**有天然的贴边能力，不需要逐行假设"一行一对边界"；缺点是走的是斜向折线、且可能绕远，所以当前版本主流程改用按行跟踪，迷宫法保留处理特殊元素和做对比实验。

### 控制逻辑

控制分两个环，分别挂在不同周期的中断里：**2ms 方向环**控舵机，**10ms 速度环**控电机，外环（视觉）给内环提供目标角度和基础速度。

#### 速度环

速度环 `speed_control()` 跑在 10ms 中断里，做三件事：**动态定速 → 差速分配 → 增量式 PID 闭环**。

**1. 动态速度**：直道（`pure_angle ≤ 1°` 且前瞻点够多）用 `straight_speed`；弯道按转向角连续减速，角度越大速度越低：

```c
float factor = 1.3f - fabsf(pure_angle) * corner_speed_slope;
if (factor < 0.4f) factor = 0.4f;        // 最低保留 40%
dynamic_speed = corner_speed * factor;
```

**2. 差速（内减外加）**：过弯时内轮减速、外轮加速，减速量与转角成正比：

```c
int16 diff = differential_add_speed2(dynamic_speed, angle);
int16 diff_outer = diff * turn_diff_outer;
if (angle > 0) { l_goal -= diff; r_goal += diff_outer; }  // 右转
else           { r_goal -= diff; l_goal += diff_outer; }  // 左转
```

**3. 增量式 PID**：左右轮各一个，输出增量累加到 PWM 占空比。公式 `Δu = kp(e-e1) + ki·e + kd(e-2e1+e2)`，同时带防堵转保护——上次输出已经顶到 ±10000 还想同向加码就强制归零，避免电机堵转烧管：

```c
float increment_pid_solve(pid_param_t *pid, float error)
{
    pid->out_p = kp * (error - pid->pre_error);
    pid->out_i = ki * error;
    pid->out_d = kd * (error - 2*pid->pre_error + pid->pre_pre_error);
    pid->output = pid->out_p + pid->out_i + pid->out_d;

    if (pid->pre_output > 10000 && pid->output > 0) pid->output = 0;
    if (pid->pre_output < -10000 && pid->output < 0) pid->output = 0;
    return pid->output;
}
```

#### 方向环

方向环跑在 2ms 中断里，输入是视觉算出的 `pure_angle`，输出舵机转角。采用 **线性 P + 平方 P + 低通 D + 陀螺阻尼** 的复合 PD：

```c
float quadradic_pid_solve(pid_param_t *pid, float error)
{
    // P：线性 + 平方（小误差温和，大误差自动加力）
    pid->out_p = pid->kp * error + pid->kp2 * error * fabsf(error);
    // D：一阶低通微分，抑制噪声
    float diff = error - pid->pre_error;
    pid->out_d = diff * pid->low_pass + pid->out_d * (1.f - pid->low_pass);
    pid->pre_error = error;

    return MINMAX(pid->out_p, -pid->p_max, pid->p_max)
         + MINMAX(pid->kd * pid->out_d, -pid->d_max, pid->d_max)
         - gyro_z * pid->kgyro;          // 陀螺阻尼
}
```

各项作用：

- **线性 P（kp=1.4）**：小误差时温和纠偏，直道不神经质
- **平方 P（kp2=0.045）**：大误差时按 `error²` 自动加力，急弯一把打够，且保留符号不会丢方向
- **低通 D（kd=9.0, α=0.3）**：抑制超调，低通过滤掉二值图边缘抖动产生的微分毛刺
- **陀螺阻尼（kgyro=−0.035）**：IMU 测到的车身偏航角速度反馈——转向打得太急时反向拉住，相当于给舵机加了"电子液压"

> **为什么需要陀螺阻尼？**
> 视觉误差最快也要一帧（约 16ms）才更新一次，而车身在这期间可能已经转过头。陀螺仪 5ms 更新一次，直接感知"现在车身正在以多快的角速度转"，在视觉看到结果之前就介入，是抑制过弯甩尾和 S 弯震荡的关键。

IMU 用的是 IMU660RB，开机静止采 100 次求零偏，角速度再做 0.3 一阶低通，积分得到车身偏航角：

```c
float calibrated = raw - gyro_z_offset;
gyro_z = calibrated * 0.3f + gyro_z * 0.7f;   // 低通
z_angle += gyro_z * 0.005f;                    // 积分（5ms 周期）
```

## 踩坑记录

***ltc E112 链接错误（RAM 不足）***：十字爬线曾新增 2820 字节全帧位图 `crawl_visited`，导致 CPU1 的 120KB DSPR1 放不下（堆、栈、CSA 都要从这块分）。解决方法是删掉静态数组，复用本帧已用完的点云缓冲和 WiFi scratch 尾部空间。教训：TC264 的 RAM 是分区管理的，"总需求小于总容量"不代表能链接通过，连续区约束会直接卡死。
